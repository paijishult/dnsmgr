## 升级步骤与兼容性

1. 备份数据库、`.env`、部署配置和业务证书；停止旧版容灾与证书任务进程。
2. 部署新源码或重新创建容器。数据库版本升级到 **1052**，原生功能标记为 **20261020.1**。程序启动会执行可重复的增量升级，需要相应建表、加列和索引权限。
3. 出现升级失败时查看私有程序日志并修复权限或异常表结构，再重试；不要手动修改版本标记来跳过检查。非标准、不完整的旧表会停止升级，避免假装升级完成。
4. SSH / 飞牛部署账户必须补填 **SSH 主机 SHA-1 指纹**。通过受信任的服务器控制台取得实际协商主机公钥的指纹；支持 40 位十六进制，或带 `SHA1:` 前缀、冒号分隔的形式。不要以首次连接到未知服务器时得到的值作为信任依据。已知服务器换主机密钥时也需重新核实。
5. 在可信服务器控制台上，可对相应 `/etc/ssh/ssh_host_*_key.pub` 文件中的第二列进行 Base64 解码，再计算 `openssl dgst -sha1`。该 SHA-1 指纹格式对应 PHP ssh2 扩展原生接口；应选择服务器实际协商使用的那把主机密钥。密码、私钥只会在匹配后发出。
6. PowerDNS / Technitium 上已有容灾、定时任务使用旧行号 ID 的，会明确提示重新编辑并选择解析记录。升级期间先保持这些任务停用，重新保存并验收后启用。
7. QQ 通知：先保存 AppID / Secret，点击“生成绑定码”，在 5 分钟内向机器人发送页面显示的完整消息。改动凭证会清除旧收件人及待用绑定码。
8. 重启计划任务进程，检查心跳、解析列表、证书状态和批量任务。Docker 需要更新镜像后重新创建容器。

新增 `cert_dns_lease` 表记录订单验证值的创建和共享归属。升级前已经存在、无法证明由当前订单创建的记录会保留，必要时人工清理。云 API 写入后进程异常中断、未能确认归属的记录也采用保留策略；避免将人工记录或其他订单的验证值当作自己的记录删除。

DNS 锁仍沿用系统 runtime 文件锁；多实例必须共享可靠锁目录。一次云 API 写入与本地数据库记录不是分布式事务；不确定结果应核对后处理。多个证书文件也不具有跨文件的文件系统事务，部署完成后仍应验收服务实际提供的证书。
