# 1067 修改、升级与验证说明

本轮围绕连续解析写入、任务并发、证书部署和失败重试修复，并增加运行中心与可选检查功能。

## 修复的行为

| 场景 | 现在的行为 |
| --- | --- |
| PowerDNS 连续新增同一 RRset | 成功写入后同步本地缓存，后续添加保留之前的值；暂停和删除保留剩余 RRset 的备注 |
| PowerDNS / Route53 记录改名或改变类型 | 源与目标在同一次提供商请求中提交，避免先删除源记录再创建目标 |
| Route53 隐藏的 Alias、特殊路由或健康检查记录 | 明确拒绝普通记录写入；不会把这些记录当作不存在并直接 UPSERT |
| Route53 修改记录值 | 同步容灾和定时任务使用的内容派生记录 ID，后续恢复能定位新记录 |
| 长记录与检测参数 | 扩大记录 ID、元数据、值、备注及计数列；允许的输入范围与数据库容量对齐 |
| 证书签发完成后部署排队 | 保存新证书、签发状态和重置部署任务在同一个数据库事务完成；任一步失败全部回滚 |
| Lucky、宝塔、耗子面板多目标部分失败 | 逐目标保存回执；整体标为失败或部分成功，重试仅处理尚未成功的目标 |
| 停用、编辑或删除正在执行的监控/定时任务 | 与工作进程使用同一把任务锁；忙时返回明确提示，不再报告已停用但仍继续执行 |
| Cloudflare 根域名暂停恢复 | 先识别暂停标记再归一化根域名，预览和实际记录状态一致 |
| HTTP 与 CLI 计划任务 | 运行同一维护队列，均包含 ACME DNS 清理重试；单个队列异常不阻止其他队列 |
| 某个通知渠道失败 | 持久化渠道结果，全部成功后才确认业务通知完成；成功渠道不因其他渠道失败而重发 |

通知渠道在一个数据库事务中入队，避免第一个渠道过早确认整条通知。相同事件去重，失败退避重试，最多 8 次；管理员可在运行中心重发耗尽的失败项。成功记录保留 30 天。通知依赖计划任务；远端已送达但本地结果保存前进程终止时，仍可能重复投递。

## 新功能入口

管理员侧栏新增「运行中心」，只对管理员后台开放，不通过 API 暴露账户配置或私钥。

- **全部任务**：汇总批量解析、容灾、定时、优选 IP、签发和部署；显示进度、错误、下次运行时间，提供暂停/恢复、批量任务取消/重试、签发/部署重试及管理日志入口。每种类型展示最近 100 项。
- **任务冲突**：发现相同记录的多个自动写入者，以及优选 IP 修改整个主机记录集产生的交叉影响。提示用于人工核对，不自动删除有意配对的定时策略；每种类型最多扫描 5000 个活动任务。
- **证书部署矩阵**：对照订单当前证书、最近部署指纹、每个目标回执及 TLS 验收结果。新证书或部署账户/配置变化会使旧目标回执失效；对成功任务手动重新部署也会清除旧回执。
- **DNS 漂移**：建立基线，按 300–86400 秒间隔检查外部变化；系统内成功变更只推进与变更前一致的基线，已有外部差异会保留。重复记录按数量比较。差异最多展示新增/移除各 100 项，基线最多 8MB/10000 条。检查范围取决于平台适配器可见的记录，未支持的路由元数据不在保证范围内。
- **凭据健康**：默认关闭。启用后每日检查 DNS 查询权限，或 Lucky/宝塔/耗子面板的只读访问；其他部署/证书平台明确显示需要人工核对，不会为探测而申请证书或部署。支持到期前 7 天提醒、7–730 天轮换周期、配置变化后的轮换时间更新。只读检查通过不代表拥有所有写权限。
- **通知队列**：查看待发送、已送达、重试耗尽及错误，手动重发失败渠道。漂移或凭据恢复后再次出现同类问题，会生成新的告警事件。

「容灾监控 → 编辑」新增 HTTP(S) 策略：TLS 链及主机名校验、允许状态码、响应必须包含文本，以及最多 4 个额外健康端点。主端点的域名固定到主记录目标，额外端点使用各自的 DNS；最多 5 个端点共用检测超时，可配置通过数量阈值。响应断言只读取前 1MB，主目标 DNS 无法解析时会判为失败。

指定主目标时，代理连接也固定到该目标，并保留原主机名进行 TLS 校验；HTTP 代理须允许相应端口的 CONNECT 隧道，不支持时检查会失败。实现依据 [libcurl CONNECT_TO 文档](https://curl.se/libcurl/c/CURLOPT_CONNECT_TO.html)。

「SSL 证书 → 部署任务」可填写多目标验收，每行 `域名:443@公网IP`，也可省略端口或 IP。域名必须在证书覆盖范围内，端口限 443/8443，最多 20 个目标、每个域名最多 16 个解析地址，总超时 1–60 秒，所有地址都通过才成功。留空保留原单站点模式（1–10 秒，任一公网地址通过即可）。部署完成但验收失败时，只重试验收。

API 新增 [HMAC v2、防重放及受支持写接口的幂等结果](api-v2.md)，旧客户端继续兼容。

## 解析批量处理

PowerDNS 与 Route53 的预览计划先在本地暂存并验证，再合并为一次提供商请求，减少逐条全域扫描。提交前检查取消与授权，提交后重新读取并核对结果。Route53 以完整旧 RRset DELETE 加新 RRset CREATE 提交，远端旧内容变化会拒绝该事务；一个请求的记录计数上限为 1000，包含 DELETE 与 CREATE。

远端请求发出后无法中途取消；取消会在下一安全边界生效。提供商超时、返回状态不一致或确认结果保存失败，都要求先核对远端和快照，再重新预览。不会盲目重试写请求。PowerDNS/Route53 的读取遇到明确的限流或临时网络错误时，最多尝试3次并短暂退避；损坏或重复的分页游标会停止读取。PowerDNS 的外部控制台写入不受本地锁控制，部署时仍需协调其他写入者。其他 DNS 平台沿用逐项读取、校验和检查点处理。

## 升级

1. 备份数据库和持久化目录，停掉旧版工作进程后替换代码或镜像。保持原有每分钟维护和容灾监控调度。
2. 首次启动自动运行可重入增量迁移：扩大 `dmtask` / `sctask` 列及部署回执 `cert_deploy.info`，增加 `health_options` 和运行功能表。只有实际检查字段成功后才保存迁移版本 `20261025.1`。需要 `CREATE`、`ALTER` 权限；大表 ALTER 可能占用时间，选择维护窗口。
3. **HTTPS 健康检查默认验证 TLS**，包括未设置 `health_options` 的旧任务。恢复监控前核对目标证书及信任链；私有 CA 应配置可信 CA，需要兼容旧行为时可在任务策略中明确关闭验证。
4. 监控/定时任务批量修改最多 50 个，避免 MySQL 5.6 的单连接单 advisory lock 限制耗尽连接；超过上限请分批。DNS 变更计划仍最多 500 项。
5. 漂移与凭据检查按需开启。维护任务每轮最多处理 2 个漂移检查、2 个凭据检查、10 条通知，繁忙时会延后；运行中心显示维护心跳。

以前已经被截断的记录元数据或丢失的 DNS 值不能通过扩大列自动恢复；此类任务需要核对快照或重新选择记录。此前版本的升级要求仍见 [1066 复核记录](changes-2026-10-20-recheck.md)。
