## 检查发现并修复的问题

| 触发条件 | 原来的问题 | 修复结果 |
| --- | --- | --- |
| Kangle 用户或管理员部署多个域名，其中一项失败 | 只要一个域名成功，整个任务就标为成功，失败域名不会继续重试 | 保存每个域名的结果；部分失败使任务失败，重试只处理未成功的域名；空域名列表也不会意外转为整个网站账号部署 |
| Kangle 登录成功 | 登录 Cookie 被写入部署日志，通用脱敏没有覆盖 | 停止记录 Cookie，并在读取旧日志时过滤整段 Cookie |
| 面板以“成功”开头返回部署结果 | `strpos()` 返回 0，被误判为失败 | 显式判断 `!== false`；HTTP 错误状态不能被当作部署成功 |
| Cloudflare 批量添加 TXT 涉及不同 DNS 账户 | 异步回调可能使用最后一个域名选择的账户 | 每个主机名独立保存所选目标；主机名验证与证书验证都修复 |
| 复制带特殊字符 ID 的解析记录值 | ID 被当成 CSS 选择器，可能找不到元素或抛异常 | 使用 `getElementById()` 定位记录，再定位相邻图标 |
| DNSLA 新增或更新时使用默认线路 `0` | 未转换为提供商要求的空线路值 | 数字和字符串 `0` 都转换为空字符串，自定义线路保留 |

### ALIAS 与本分支的适配

- 支持的提供商才展示 ALIAS；跨域名批处理要求全部选中域名都支持。后台表单、API 和预览执行也检查能力，不能仅靠隐藏选项限制。
- PowerDNS 写入时补全目标域名尾点，预览结果比较与自动任务记录 ID 同步接受这种规范化，避免“写入成功但校验失败”。
- ALIAS 与 Route53 的 AliasTarget 是不同的提供商能力，未放开 Route53 已有的特殊记录保护。ALIAS 也不加入直接 DNS 查询类型按钮。

### SamWaf 使用与适配

在“SSL 证书 → 自动部署账户”中选择 SamWaf，填写控制台地址、开放平台 API Key 和代理选项。控制台地址可带安全访问路径。在部署任务中填写证书夹 ID；留空时匹配已有的相同证书或创建证书，并把 ID 保存给后续续期使用。SamWaf 中的主机绑定仍在其面板配置。

连接测试查询一条证书列表，不上传证书。新增时按实际证书 SHA-256 指纹匹配，不使用上游会损失大整数精度的 `hexdec()` 序列号比较，也不依赖 CN 字段。列表最多读取 10000 项，分页重复或不完整会停止；已有 ID 更新前核对目标并保留导入路径，更新后再次核对证书指纹和私钥内容；相同证书缺少对应私钥时不会直接报告成功。接口错误中的 API Key 和上传私钥经过脱敏。

适配依据为 SamWaf 官方的[证书 API](https://github.com/samwafgo/SamWaf/blob/75944f5371139833e92058564332aeb27def048e/api/waf_ssl.go)与[证书存储服务](https://github.com/samwafgo/SamWaf/blob/75944f5371139833e92058564332aeb27def048e/service/waf_service/waf_sslconfig.go)。本次未连接真实业务账户。
