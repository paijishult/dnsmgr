## 新增功能与使用方法

### DNS 快照、预览和回滚

解析页面进入“变更历史”，可手动创建快照、预览 JSON 变更或选择历史快照生成回滚预览。每次执行前保存恢复点，界面展示修改前后差异；必须使用服务器生成的一次性预览凭证执行。

预览凭证有效期 10 分钟，绑定用户/API 密钥和域名账户。每个用户跨 API 密钥最多保留 3 个未消费的预览，创建更多预览会清理最早的计划；单个计划连同原记录不超过 2MB，避免未执行的随机预览令牌积累文件缓存。执行时校验整个域名记录的指纹，检测到预览后或执行中的外部修改便停止。每一项操作后核对实际结果与未修改记录，平台返回成功但结果不一致时也停止。

缓存写入、旧预览清理或一次性凭证删除失败时拒绝继续，避免存储异常时发出不可用预览、重复消费或突破保留上限。每个域名保留最近 100 个快照；单快照最多 8MB，域名读取上限 10000 条，单次计划最多 500 项、输入 1MB。快照只包含解析记录，可能含敏感 TXT 值，应按业务数据保护备份。

根域名 NS/SOA 不支持通过预览修改。QingCloud、AWS、PowerDNS、Technitium、腾讯 EdgeOne、阿里云 ESA 的部分原生元数据无法无损还原，因此拒绝自动快照回滚，仍可查看快照和使用原生表单调整，避免静默丢失配置。

### 后台批量任务中心

在预览确认框选择“加入后台任务”，使用原有每分钟 `php think certtask` 或 HTTP cron 执行，无需额外队列进程。任务中心显示进度、逐项结果、错误、历史快照，并支持失败后重试及请求取消。

任务只接受已预览的服务器端计划。逐项确认成功后保存剩余计划与新的指纹，后续只执行剩余项目；若发生“平台已执行但检查点未保存”的不确定中断，指纹检查会阻止盲目重放，需要重新预览。取消在当前平台调用结束并确认结果后生效，已完成项目不会自动撤销。

每个用户最多 20 个待处理/失败任务，计划执行窗口 24 小时，已完成与取消任务 30 天后清理。每轮最多取 10 个任务，采用约 15 秒的合作式时间片；单次云 API 调用可能超过该时间片。密码/API Secret 重置、用户禁用、授权域名/Scope/IP 白名单变更均在执行前及项目之间重新核实。

状态：`0` 排队、`1` 处理中、`2` 完成、`3` 失败、`4` 取消。失败重试沿用原计划；DNS 已有其他变化时应重新预览，不能强制覆盖。

### 证书线上验收

部署任务表单可选开启“线上 TLS 验收”，目标须在订单证书域名范围内，端口仅允许 443/8443、超时 1～10 秒。通过公共 DNS 解析、校验并固定公网 IP 后读取 HTTPS 证书，校验证书链、主机名和 SHA-256 指纹，不跟随重定向，也不使用环境代理。

部署任务状态：`0` 待部署、`1` 完成、`2` 部署完成待验收、`-1` 平台部署失败。状态 2 重试只验收，不再次调用部署提供商。修改部署目标或切换证书会清除旧验收结果并重新排队；只修改备注不会触发重新部署。

## 数据库与升级

- 新表：`dns_snapshot`、`batch_task`，SQL 位于 `app/sql/features.sql`，全新安装脚本已同步。
- `FeatureMigrationService` 使用独立 MySQL 锁执行幂等增量建表，校验所有必需字段后才写入 `native_features=20261019.1`。部分失败不写成功标志；HTTP 返回 503 并记录日志，可修复权限后重试。
- 原 `dbversion=1051` 升级链保留。新表均为 InnoDB/utf8mb4，不删除或重写现有业务数据。
- 升级前备份数据库、`.env`、系统密钥与持久化目录；停止旧版长驻 `dmtask` 和旧 cron 调用，完成代码/依赖更新后重启工作进程。不要混用旧、新版本工作进程。
- 升级账户须有 CREATE TABLE 权限。应用需要 PHP 8.2+ 与现有扩展、MySQL 5.6+；数据库连接锁使用独立、非持久、不可自动重连的主库会话，兼容 MySQL 5.6 每会话仅一个命名锁的限制。
- DNS 写入锁与安全计数位于共享 runtime 文件目录。多个 Web/任务实例必须共享同一持久化 runtime；跨主机且文件锁语义不可靠的部署不在此锁方案的保证范围内。不要在运行中删除锁文件。
- 新表为增量功能数据。回退代码前停止工作进程并处理排队任务；保留新表即可，勿直接重新运行含 DROP TABLE 的安装脚本。解析回滚应通过快照预览完成，应用版本回退不会自动撤销云端变更。
- 外部 HTTPS 客户端现要求可信 CA。自签名面板应配置可信证书/CA；Kubernetes 可使用原生 kubeconfig CA，只有显式的 `insecure-skip-tls-verify: true` 才关闭校验。监控健康探测保留原有自签名检查语义，不携带部署凭据。
- `runtime/limits` 文件使用稳定 inode，避免删文件造成并发计数分裂。常规清缓存不会清除安全限制；如确需整理历史限制文件，应停所有 Web/任务进程后进行，重新启动会重置对应限制窗口。
- IP 获取的默认/`auto` 模式不再将私网或回环来源自动视为代理，统一取 `REMOTE_ADDR`。反代且已设置 IP 白名单的实例升级后，需要在“API 密钥 → API 设置”核对地址并明确选择可信代理提供的头部模式；代理须覆盖对应头部，源站应限制为仅可信代理可达。

## 新增 API

统一 `POST /api/...`，沿用现有签名。后台请求使用 CSRF 令牌；签名 API 使用原有认证中间件。

| 路径（省略 /api） | 参数 | Scope |
| --- | --- | --- |
| `/record/history/data/:id` | offset、limit；snapshotid 可选，读取记录详情 | record:read |
| `/record/snapshot/:id` | label（可选） | record:write |
| `/record/preview/:id` | operations（JSON 数组） | record:read |
| `/record/apply/:id` | token | record:write |
| `/record/rollback/preview/:id` | snapshotid | record:write |
| `/batch/data` | offset、limit | record:read |
| `/batch/details` | id | record:read |
| `/batch/enqueue` | did、token、name（可选） | record:write |
| `/batch/task/retry`、`/batch/task/cancel` | id | record:write |

操作示例：`[{"action":"add","name":"www","type":"A","value":"192.0.2.1","ttl":600}]`。预览返回 token、expires 和 changes；应用/入队均消费该 token，二选一。任务列表和详情不返回身份凭据或内部执行计划。部署任务 config 可额外包含 `_verify_tls={"enabled":true,"host":"www.example.com","port":443,"timeout":5}`。
